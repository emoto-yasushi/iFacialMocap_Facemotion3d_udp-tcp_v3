Manual start and auxiliary messages

## FMV3_iOS_to_PC_EN

Face Motion v3 | Receive Data Structure (iOS → PC)

Standard ports • contract_revision = 4 • little-endian • no padding • layouts below are unfragmented

Default ports

iOS listeners (UDP / direct TCP)

PC listeners (UDP / manual TCP)

iFacialMocap

49983 / 49984

49983 / 49986

Facemotion3d

49993 / 49994

49983 / 49986

SCHEMA: message_type = 3 (0x03) | At startup, schema changes and retransmission

Common header

40 B

Start information

20 B

Schema JSON

UTF-8 / variable length: J bytes

Unfragmented total = 60 + J bytes. Header session_id and start-info client_nonce have different roles.

Main SCHEMA header settings

Field name

Value

magic / header_size

FMV3 / 40

schema_id

Current schema ID (1 or higher)

flags / sequence / source_token

All 0

20 + JSON byte length

part_index / part_count

0 / 1 if unfragmented

Full payload length if unfragmented

session_id is 8 B; schema_id is 4 B.
The transmit diagram lists all common header fields.

client_nonce versus session_id
HELLO: the PC puts its nonce in the header.
SCHEMA: the header carries the iOS session_id.
Start info echoes the PC nonce; manual start uses 0.
UDP ACK: echo the SCHEMA session_id.

Start information: 8 + 2 + 2 + 4 + 4 = 20 B

Schema JSON: exactly 9 keys (example with 3 items)

{
  "schema_version": 1,
  "app": "iFacialMocap",
  "profile": "ifacialmocap-stream",
  "blend_names": ["eyeBlinkLeft", "eyeBlinkRight", "jawOpen"],
  "blend_encoding": "i16",
  "blend_unit": "percent",
  "pose_layout": "head_rxyz_pxyz_rightEye_rxyz_leftEye_rxyz",
  "rotation_unit": "degree",
  "position_unit": "meter"
}

schema_id belongs in the header. Use blend_encoding; do not use a value_type key.

FRAME: message_type = 4 (0x04) | Numeric values in schema order

Common header

40 B

N signed BlendShape integers

i16: 2N B / i32: 4N B

Head + right eye + left eye

Float32 × 12 = 48 B

N = number of blend_names, not a fixed 52. For N=52, i16, unfragmented: 40 + 104 + 48 = 192 B.

State stored in the header

flags bit 0: tracking / bit 1: playback
source_token: used only on FRAME
schema_id: identifies the schema
sequence: frame number

Integer values and mapping

Use the 3-name order in the JSON above.
[0, 0, 71] means jawOpen = 71.
Negative values are allowed: -25 → -0.25.
Names, count and type are not repeated in FRAME.

Order of the 12 pose values

Head: rx, ry, rz, px, py, pz
Right eye: rx, ry, rz; left eye: rx, ry, rz
Rotations: degrees. Position: meter-derived values after app scaling, axis conversion and calibration.

UDP fragments: [40 B header + payload fragment]. Reassemble the payload before parsing SCHEMA or FRAME.

SCHEMA: at most 576 B per UDP datagram, including its header. The 20 B start information occurs once at the start of the logical payload, not in every fragment.
TCP: frame using the 40 B header and chunk_length. Schema changes: new SCHEMA → new FRAME; UDP waits for the new schema ACK.
